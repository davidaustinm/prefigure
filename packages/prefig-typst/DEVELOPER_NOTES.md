# prefig-typst

Author and render [PreFigure](https://prefigure.org) diagrams from inside a
Typst document. Typst drives; the PreFigure core (the Rust port under
[`packages/prefig-rust`](../prefig-rust)) runs as a Typst **wasm plugin** and does
all the geometry and label placement. Typst supplies the one thing a plugin
cannot compute for itself — text measurement — using its own layout engine.

```typ
#import "@preview/prefigure:0.1.0": prefigure   // or a local path, see below
#prefigure(read("diagram.xml"))
```

The diagram's **text and math are rendered by Typst** — text overlaid as live,
selectable content and every `<m>` converted with
[mitex](https://github.com/mitex-rs/mitex) — so both match the document's fonts.
A diagram with any math is therefore drawn in this native mode; a **math-free**
diagram can instead bake its text into a self-contained SVG with `labels: "svg"`.
Both are detailed below.

The design and its rationale are in
[`TYPST_PLUGIN_PLAN.md`](../../TYPST_PLUGIN_PLAN.md) at the repo root; this README
is the how-to and the record of what is actually built.

## Why a plugin can't just call Typst back

A Typst plugin speaks the [`wasm-minimal-protocol`](https://github.com/typst-community/wasm-minimal-protocol):
bytes in, bytes out, exactly two host imports, no callbacks, no async. So the
plugin cannot ask Typst to measure text mid-build. The pipeline inverts that into
a **metrics-injection handshake** (four passes, orchestrated by
[`src/lib.typ`](src/lib.typ)):

| Pass | Where | What |
|------|-------|------|
| **A** enumerate | `plugin.extract_measurables(source)` | returns the distinct text runs a build will measure, each with its (concrete) font — see [`extract`](plugin/src/lib.rs) |
| **B** measure | [`src/measure.typ`](src/measure.typ) | Typst measures each run with `measure()` + the `top-edge`/`bottom-edge` baseline split |
| **C** build | `plugin.build(source + metrics)` | PreFigure lays out and draws everything, answering `measure_text` from the injected table |
| **D** embed | `image(bytes(svg), format: "svg")` | the finished SVG goes into the document |

Pass A does **not** hand-mirror PreFigure's label walk (which would drift from the
real build). It runs an actual build with a *recording* text backend and keeps
the set of measurement requests — the same code path Pass C takes, so the two
cannot disagree. The shared key ([`measure_key`](../prefig-rust/prefig-core/src/core/label_tools.rs))
guarantees every Pass A run is consumed in Pass C.

## Two ways to render the text: `labels: "native"` vs `"svg"`

Passes A and B are identical in both; they differ only in how Pass C/D deliver the
text.

- **`labels: "native"` (the effective default).** PreFigure omits the `<text>` and
  returns each run's absolute baseline position; the Typst side
  ([`src/native.typ`](src/native.typ)) lays **live Typst text** on top of the
  embedded SVG at those coordinates. The text is real, selectable Typst content in
  the document's font; the baselines line up pixel-for-pixel with the baked version
  because the metrics were measured the same way.
- **`labels: "svg"`.** PreFigure draws each run as an SVG `<text>` element, so
  Pass C returns one complete SVG that Typst's resvg backend rasterizes.
  Self-contained; the SVG *is* the diagram.

`labels` defaults to `"svg"`, but math is always rendered by Typst and overlaid as
native content, so a diagram with **any** math (including axis labels and tick
numbers, which are math) is drawn native — text and math overlay together in one
pass. `labels: "svg"` therefore only takes effect for a **math-free** diagram
(pure geometry, or plain-text labels with no axes):

```typ
#prefigure(read("diagram.xml"))                    // native: live Typst text + math
#prefigure(read("plain-geometry.xml"), labels: "svg")  // math-free → self-contained SVG
```

Geometry is always in the SVG; in native mode the text and math are lifted out and
rendered by Typst on top of it.

### Math by Typst (mitex)

Every `<m>` — whether authored in the source or generated by PreFigure — is
converted with mitex, so math matches the document's math font. Nothing extra is
required; a plain `read()` does it:

```typ
#prefigure(read("diagram.xml"))                    // math by Typst (mitex)
```

The plugin ships without a math engine of its own. If you specifically need math
**baked into a self-contained SVG** (no live Typst overlay), rebuild the wasm with
RaTeX embedded — `wasm-interface/build.sh --with-math` — which is ~3.7 MiB larger; the
default 1.7 MiB build has no math engine because Typst does the math.

For a diagram **authored in Typst**, write math the Typst way — `$…$` — using
[xmlit](https://github.com/siefkenj/typst-xmlit), and pass its extracted
equations so the authored equations are drawn verbatim (not round-tripped through
LaTeX):

```typ
#import "@preview/xmlit:0.1.3": make-tags, xml-to-string
#let (diagram, coordinates, label, ..) = make-tags("diagram", "coordinates", "label", ..)
#let doc = diagram(.., label(p: "(1,1)")[the curve $y = x^2$])
#let (xml, math-items) = xml-to-string(doc, extract-math: true)
#prefigure(xml, math-items: math-items)            // text *and* math by Typst
```

`extract-math: true` replaces every `$…$` with a sentinel `⟦math-N⟧` in the XML
and returns the equations in `math-items`. PreFigure lays the diagram out from
each equation's Typst-measured size and leaves its slot empty; `native.typ` then
overlays it as native Typst content. Passing `math-items` implies native labels
(text and math are one coherent overlay pass).

The `math-items` route is only for diagrams **authored in Typst**. An existing
figure whose math is already LaTeX in the `<m>` tags needs nothing at all — every
`<m>` body is converted with mitex, so the figure's math renders in the document
font on a plain `read()`. This is how
[`typst-math-figures.typ`](examples/typst-math-figures.typ) renders the level-curve
and other math-heavy diagrams straight from the test corpus:

```typ
#prefigure(read("figures/implicit.xml"))   // \frac{2}{3\sqrt{3}}, … via mitex, by default
```

Math that PreFigure generates *itself* — axis labels and tick numbers — has no
sentinel, but `prefigure` enumerates it (via a Pass-A collecting backend) and
converts it to Typst math with [mitex](https://github.com/mitex-rs/mitex), so a
whole diagram's math renders in the document font. This is a small, fixed grammar
— `\text{…}` numbers (incl. comma-thousands `\text{1{,}000}`), single-letter axis
labels, log-scale `10^{j}` / `k\cdot10^{j}` ticks, and π-format `\frac{a\pi}{b}`
ticks — and mitex 0.2.7 renders all of it under Typst 0.15.1. (Typst-authored math
never takes this path: it comes from the `$…$` a sentinel points at.) mitex is
imported lazily, and only when a diagram actually has a LaTeX `<m>` body to convert
— so math-free and Typst-authored (sentinel-only) diagrams never pull the
dependency.

Two caveats: native math is drawn at the default label size (14px); and its
baseline is aligned to the text baseline explicitly (an equation's baseline is
not at the top of a Typst "baseline" box the way a text run's is, so the overlay
measures each equation's ink-top→baseline height and drops the box onto the
baseline — see [native.typ](src/native.typ)).

**Fonts differ between the modes.** In `svg` mode the label font is the one
PreFigure names in the SVG — the `<label font=...>` attribute (default
`sans-serif`) resolved through the font map below to a concrete family that resvg
renders. In `native` mode the text is ordinary Typst content, so it **inherits
the document's `#set text` font** (weight and style still come from `<it>`/`<b>`,
size from the label); the font map and the `<label font>` attribute do not apply.
To force a family in native mode, wrap the call — `#{ set text(font: "…");
prefigure(src, labels: "native") }` — or use `#set text` document-wide.

Rotated and scaled labels overlay with the same handedness the baked SVG uses
(PreFigure rotates in y-up math coordinates, so the screen rotation is by
`-angle`), and both transforms pivot about the point the placement targets — the
start of the baseline, which is the *top* of a text box but the *bottom* of a
math box. A regression fixture guards both, for text and math alike; see
`tests/fixtures/native_stress.xml`.

Colours are read exactly as resvg reads the baked `<text>`, so the two modes
agree: the full set of CSS/SVG colour names, `#rgb`/`#rrggbb` hex (with or
without alpha), and the `rgb()`/`rgba()`/`hsl()`/`hsla()` functional forms in
either the legacy comma or the CSS 4 space-and-slash syntax — PreFigure writes
`rgb(r,g,b)` itself for a computed colour. A colour that cannot be read is an
error rather than a label silently drawn in black; see
[`src/color.typ`](src/color.typ).

## The font contract

Typst's SVG renderer does not support generic font families: it draws
`font-family="sans-serif"` as serif, and — worse — measuring one family while
rendering another would silently invalidate the metrics. So both sides use one
map from PreFigure's generic names to concrete families
([`src/fonts.typ`](src/fonts.typ)); Pass B measures the concrete family and Pass C
writes that same family into the SVG. Because Typst's `measure()` and its SVG
renderer share one font book, a family Typst can measure is one it can render.
Override per document:

```typ
#prefigure(read("diagram.xml"), fonts: (sans-serif: "Fira Sans"), width: 10cm)
```

## Building the plugin

Requires the `wasm32-unknown-unknown` Rust target.

```sh
cd wasm-interface
./build.sh              # default: no math engine (~1.7 MiB) — Typst does the math
./build.sh --with-math  # embed RaTeX for baked-SVG math (~5.4 MiB)
```

`build.sh` writes `src/prefig_typst_plugin.wasm`, the artifact `src/lib.typ`
loads. It is checked in so the package works without a Rust toolchain. The default
build omits the RaTeX engine — its embedded KaTeX fonts are ~3.7 MiB — because math
is rendered by Typst (mitex). Use `--with-math` only if you need math baked into a
self-contained SVG.

## Using it locally

There is no published Typst package yet; import by path and compile with
`--root` at the repo root so the relative `read()`/`plugin()` paths resolve:

```sh
typst compile --root /path/to/prefigure examples/demo.typ demo.pdf
```

## Testing

```sh
TYPST=/path/to/typst tests/run.sh
```

This runs the native protocol tests (`cargo test`, no wasm/Typst needed) and,
if a `typst` binary is found, the Typst-native render test that compiles every
fixture and asserts the Pass A invariants. Verified against **Typst 0.15.1**.

## Math rendering

Math is rendered by **Typst**. The plugin returns each `<m>`'s dimensions and
leaves the glyphs to Typst — the
[`SuppliedMathMetrics`](../prefig-rust/prefig-core/src/core/label_tools.rs) backend.
Typst-authored math comes from the sentinel's `$…$` (via `math-items`); every other
LaTeX `<m>` body — both what a figure authored and what PreFigure generates (axis
labels, ticks) — is converted to Typst math with mitex on the Typst side (see
above). Because Typst does the math, the shipped wasm carries **no math engine**.

The optional `--with-math` build re-embeds PreFigure's pure-Rust
[`ratex`](../prefig-rust/prefig-core/src/core/ratex_math.rs) engine (KaTeX fonts
embedded), which renders every `<m>` inside the module for a fully-baked SVG.
Output is KaTeX-styled, not MathJax-styled (`ratex_math.rs` carries a hand-tuned
`EX_PER_EM = 2.25`; re-tune if sizing looks off). One wrinkle drives the two-step
build: the RaTeX font loader drags in `wasm-bindgen` imports (via
`ratex-unicode-font → system-fonts → web-sys`) that Typst rejects — a plugin may
import nothing outside module `typst_env` — so `build.sh --with-math` runs
[`tools/stub-imports`](wasm-interface/tools/stub-imports) to replace those (dead, once
fonts are embedded) imports with trapping stubs. The default build pulls no such
imports and needs no stubbing.

## Known limitations

- **Tactile / braille is out of scope.** The build uses the no-op braille
  backend; embossed output has no meaning in a Typst document.
- **`<image>` (SVG `foreignObject`) renders as nothing** in Typst's resvg
  backend, so diagrams using raster/foreign images will drop them.
- **Embed scale.** Typst reads SVG user units at 96 dpi (1px = 0.75pt), so a
  300-unit diagram is 225pt unless you pass `width:`.
- Synthetic italics: if the concrete family lacks an italic face, Typst measures
  and renders an upright glyph — pick families with the faces you use.
